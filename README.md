版本 1.3.0。原生 Android 应用，最低 Android 5.0（API 21），compileSdk / targetSdk 37（Android 17）。界面和数据均保存在本机，不需要自建服务器。

## 使用

1. 安装随附的调试版 APK，点首页“同步”，或打开“导入 → 登录南京林业大学教务系统”。登录入口为 https://jwxt.njfu.edu.cn/jsxsd/framework/xsMainV.jsp 。
2. 在学校网页登录，进入教务主页并等待课表加载。Cookie 由学校下发；应用自动获取，不需要输入或复制 Cookie。
3. 应用从课表请求、页面字段或资源请求记录识别登录后分配的作息方案与学期；点登录页底部学期文字或右上角菜单可以修改学期，例如 2026-2027-1。
4. 如需查看一周，可在登录页右上角菜单点“查询指定周”，填写该周周一日期（例如 2026-8-31）；这个入口用于在线查看。整学期离线缓存由同步入口保存。
5. 点“登录完成，导入课表”，核对完整课程名、教室、节次和周次后确认替换。
6. 到“设置”确认第一教学周的周一日期和学期周数；点“设置每节开始时间”进入滚轮时间编辑页，再点“确认并保存学期设置”。默认作息只是模板，不代表学校官方时间。
7. 开启上课提醒，通过滚轮设置提前 0–180 分钟。Android 13 及以上允许通知；Android 12 及以上还可允许“精确闹钟与提醒”。可发送测试通知检查通知通道。

从本地文件导入支持本程序导出的 JSON，以及所提供接口的 HTML 响应。适合接口暂时不可达或离线核对。JSON 导出只包含课程，不包含账号、登录会话、学期设置或提醒设置。

每次导入会关闭提醒，并要求重新确认学期日期和作息，以免新学期使用旧日期。手动修改课程后会立即重排提醒。导入前建议先导出原课表。跨周、单双周和不连续教学周都可用，例如“1-16单”“1-8,10-16”。

## 竖屏界面与学校登录

首页默认采用月历平铺：每个日期显示课程标签，点日期直接打开当天完整课程和实际时间；支持跨月浏览与回到今天。还可切换“周历”和“日程”。导航箭头使用独立绘制图标，统一居中，不依赖字体字符。周历网格使用设置中的每节开始、结束时间（如08:30、09:20），不再以整点画线；短课时保留可读高度，午休等空档仍可见，重叠课程并排放置。所有视图均适配竖屏；周历点周次可以选周，左右箭头切换。

学校登录使用系统手机 WebView User-Agent。工具栏保持紧凑；键盘显示时将“登录完成，导入课表”固定在键盘上方，只收起学期文字与状态说明，网页继续调整可用空间。仅对含密码表单的窄屏页面补充 viewport、滚动和越界表单修正，不改动输入值和提交行为。登录后检测选课临时页时会转到指定教务主页；同源框架课表可作为读取回退路径，导入前仍保留完整性核对提示。

## 课程时间设置

在“设置 → 设置每节开始时间”中：

- 每节开始时间使用“时、分”双列滚轮，24小时制，精确到分钟。修改某节后，前面的节次保持原值，后续节次按各节时长与默认课间休息自动重新计算。午休或晚休可继续修改对应节次开始时间，后续再随之重算。
- 课程时长为1–180分钟，修改后统一计算各节结束时间。升级时保留原有开始、结束时间和午休；旧设置如有不同时长，会在编辑页标注。
- 默认课间休息为0–180分钟，用于新增节次与批量排列。仅改变默认课间，不会覆盖已有的单节时间。
- “按时长与课间重新排列”会先展示具体结果，确认后从第一节开始重新生成全部节次；该操作会覆盖单独设置的午休、晚休。之后仍可逐节微调。
- 每天可设置1–20节，已有课程用到的节次不可删除；开始时间须有序且不重叠，结束时间不可超过当天23:59。
- 点“保存课程时间”后更新课表和后续提醒；返回时可以保存、放弃或继续编辑。

## 浅色与深色主题

应用跟随Android系统的普通/深色模式自动切换，覆盖月历、周历、日程、设置、课程详情和滚轮弹窗。主文字、次要文字、课程色块与按钮分别调整颜色；两套主题的关键文本对比度检查达到4.5:1以上。学校网页登录内容保持原站样式，应用自己的工具栏与导入按钮跟随系统主题。

教学周采用紧凑区间，例如“6-17”“1-15单”“1-8,10-16”，不连续周次不会合并成错误的连续区间。

## 接口与解析

应用请求学校同源接口：

    https://jwxt.njfu.edu.cn/jsxsd/framework/mainV_index_loadkb.htmlx
    ?rq=<all或具体周一日期>&sjmsValue=<登录后自动识别>&xnxqid=<学年学期>&xswk=false

在线同步使用当前学校网页登录产生的 Cookie 和同一 User-Agent，在后台线程执行 HTTPS GET。不写死作息方案ID、学生标识或登录令牌。不跟随接口响应的登录重定向，不跳过 TLS 校验；会话失效时提示重新登录。登录页没有原生 JavaScript 桥，也不读取密码表单。离开导入页时清理 Cookie、WebStorage 和缓存；旋转屏幕时保留当前登录状态。

NjfuParser 使用 jsoup 解析 HTML，不执行响应中的脚本、不请求其中的二维码或图片。解析 .item-box 中的完整课程信息，支持异常嵌套、多条详情、跨大节重复、同一课程不同周次不同节次；不依据“第一大节”等行号猜测实际节次。显示教师字段已在接口中截断时会提示手动补全。无法解析的课程会在预览中列出，不会猜测排程。

## 提醒

按 Asia/Shanghai 计算课程时间，设备时区改变后仍按学校时区提醒。使用 AlarmManager + BroadcastReceiver，只排程下一次提醒；收到提醒后继续排程下一次。同一时刻多门课分别通知。重启、应用升级、设备时间或时区修改、精确闹钟授权变化时恢复排程。

同一门课的提醒记录同时包含课程、开课时间和当前提醒目标时间。已经按较长提前量发送后，缩短提前量会重新安排新的提醒；相同目标时间不会因为打开应用或重复回调而重复发送。课程在开始上课时才过期：目标时间已到但尚未上课时会补发一次；已经开课的课前提醒不补发。提前0分钟按开课时刻触发，允许系统回调最多30秒的延迟，打开应用不会新建已开课课程的0分钟补发。

升级时，旧版本仅按课程标记的记录会重新按当前提前量计算，尚未上课且当前提醒时间已到的课程可能补发一次。提醒发送失败不会写成已送达，重试也不会跨过课程有效期。

没有精确闹钟授权时使用可能延迟的备用闹钟；不会把已经开始的旧课程集中补发。设备关机、系统强行停止、禁用通知、厂商后台管控可能导致缺失。强行停止后重新打开应用；撤销精确闹钟授权后也请重新打开以重排备用闹钟。系统静音、勿扰或通知通道设置会影响声音。

## 构建

- JDK 17 或 21。
- Android Studio 中安装 Android SDK Platform 37 / 37.0 和 Build Tools 36.0.0。
- Gradle Wrapper 9.4.1、Android Gradle Plugin 9.2.1。
- jsoup 1.23.2 和 desugar_jdk_libs_nio 2.1.5，用于 Android 5 的 Java 标准库兼容。

用 Android Studio 打开本目录，或设置 ANDROID_HOME / local.properties 指向自己的 SDK 后执行：

    .\gradlew.bat :app:assembleDebug :app:lintDebug

APK 位于 app/build/outputs/apk/debug/app-debug.apk。调试签名由开发机生成；随附 APK 使用本次构建的调试签名。自己重新构建时签名可能不同，需要卸载原调试版后安装。发布前应使用自己的发布签名。

## 目录

- app/src/main/java/cn/edu/njfu/timetable：原生界面、接口请求、HTML 解析、离线数据和提醒。
